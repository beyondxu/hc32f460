# CE继续缩短对照：四段数据建立等待各3个NOP

分支 `codex/printer-ce-setup-3nop`，以3e7e161为源码基础。
本次参照的是用户当前手工改过的版本：CE后100ns已去掉、四段S后的等待已去掉，数据前仍为5个NOP。
不是以未修改的3e7e161作为纸面对照。

当前用户证据：连续打印可先黑后青，长停顿后可能很淡或无墨；不能仅据此确定能量过大或堵塞。
继续探索较短CE，保持BK两份重复打印分支及图像、喷头、供电、速度和擦拭条件一致。
不要切换BK自由图片模式来做这一档对照。

## 唯一进一步缩短项

实际列打印函数中四处 FAST_SET_DATA 后各从5个NOP改成3个NOP。
200MHz、每NOP一周期的名义估算是每段减少10ns，合计40ns。
这是一档相对5-NOP更短的中间值；用户已试过零NOP，这不是比零NOP更短的新极限。
CE实际宽度不由NOP数单独决定，不能声称本版已实测为某个微秒数。

CE前地址建立delay_100ns保留，CE后的delay_100ns不执行，四段S之后无额外NOP。
四个S低电平delay_ts_400ns原封不动，S4完成后才关闭CE。
锁存清零、IRQ保存恢复、地址及列末等待、数据映射和电源命令不变。
全局delay_40ns仍保留原5个NOP，不影响CE低期间的清零/其他函数。
使用仅限实际列函数的内联3-NOP等待，避免全局改动扩散。
