# M0333N 连续 CE 完整驱动候选：CONT_CE_v1

本版本取代逐地址切换 CE 的候选实现。依据 M0333N V1.2 印刷页 11、12 及用户与技术支持确认：CE 在上电流程拉高，正常打印、停止、重置均保持高，下电流程才拉低。旧的 CE=1.7us 测量不能代表此版本 tFire。

## 实现

- 保留原 GPIO 映射、25 地址表和所有共享延时函数的机器代码来源；不改 BK、SPI 协议、统计头、图案或走纸。
- 上电：CE/A/D=0，S全低；VL开，等待，VP开，等待，S全高，等待，CE高；在 A=0、D=0 下采样 S1..S4 进入空闲。三个等待沿用 delay_10us，不用规格表可疑的 0.5ns 数值推导 NOP。
- 空闲时预先生成 26 组 GPIO 数据，共 520 字节栈数组。前25组来自原100字节；第26组再次选 Add25、四段 D=0。完整函数在 GCC M4 -O2/-Os 下栈帧均为568字节；项目配置栈8KB。
- 一个相同循环发送全部26组。地址与四段D直接写GPIO，四段S低脉冲沿用现有 delay_ts_400ns。连续段没有 CE 操作、日志、源数据读取、查表、DWT计时、额外 1us 等待或中断服务。CPU加载预解码字、循环开销和GPIO写入都计入真实 tFire。
- 25组与停止组之间没有专门分支、清零助手或额外计算。停止组四个S均完成后才 A=0，并在 CE高、A=0、D=0 下再执行全局重置。随后恢复调用者 PRIMASK，返回等待通信。
- 只屏蔽连续发送及收尾重置这段有界的短窗口，不屏蔽整次电机/SPI任务。不能在活跃地址段单步或下断点。
- 下电：CE高时先进入全局重置；CE低，等待，S低，等待，VP关，等待，VL关。重复ON不重启已开启会话；重复OFF不重新使能CE。
- 保守地在上一列停止并重置完成后再留至少60us空闲，防止直接连续调用时单喷嘴超过18kHz。这是本次诊断留量，不是厂家规定的每地址休止时间；正常BK列间隔远大于该值。DWT只在无加热的准备/空闲阶段使用，不重置全局CYCCNT。计数器不能运行时不上电，并报错。
- NULL或未上电调用不发送。原 fix/xx/standalone 入口统一走这个协议，防止遗留逐地址CE流程混入新会话。

## 部署

这是源码候选，尚无本机完整 Keil 链接、下载及带墨验证。不要把 GCC 编译或模型测试当成实机时序验证。

1. 备份当前本地 tph_m0333n.c。完整驱动为 `source/tph_m0333n.c`，无需修改头文件或添加 Keil 编译单元。
2. 用新完整驱动更新文件。如果本地共享延时函数有校准修改，从备份保留整段 delay_* 定义，尤其 `delay_ts_400ns`；本仓库原延时定义没有调整。不要仅替换 Fire 函数：它依赖新的上下电和空闲状态助手。
3. Rebuild All、下载HC32、整机重启。BK保持之前同地址D1/D2/组合对照版本。
4. 上电日志应包含 `[TPH Power] CONT_CE_v1 ON CE=HIGH idle=Ax0_Dx0; rails unmeasured`。若有 `idle clock unavailable`，先解决DWT时钟，不能将打印统计当作已打火证明。
5. 先按此前可行的移开喷头测逻辑方法核对波形：CE持续高；S低至少0.38us；D覆盖对应S低窗口；相邻地址的同一个S下降沿间隔才是tFire；Add25到停止组也相同。图上的1.70us是目标，源代码没有声称其时间已被校准。保留15V，不同时拆MOS或改电压。若实际tFire不合适，先根据实测调整，不直接带头打印。
6. 时序确认后打印相同测试两组，不在组间擦拭。提交完整照片、是否擦拭/等待、BK与HC32日志。

`tFire` 不能只用 4*0.4us 推算；包括下一组的预解码字加载、地址/D GPIO写入和循环开销。停止组与前25组走同一条代码路径，降低最后一组延迟差异，但实机总线、编译器和缓存仍需要边沿测量。

## 验证范围与排除边界

- 五项自动检查通过：实际GPIO/LUT模型、真实M4对象、握手、行统计及独立RX CRC。
- GPIO模型覆盖六个D域、混合/全零/末地址数据，26组相同逻辑节拍，停止组仍为Add25，D/A覆盖S采样，CE保持高，电源顺序，保存/恢复两种PRIMASK，未上电/NULL、计数回绕和DWT失败。ASan/UBSan通过。
- GCC Cortex-M4 -O2/-Os 全驱动编译无警告；连续发送段没有函数调用；四段采样NOP及重置采样保留。
- 这些仅验证实现逻辑与编译结构，不能证明物理tFire、喷墨、供电或供墨正常，不能据此排除喷头/接触/能量因素。

回退应恢复整个备份C文件并重新编译下载、整机重启，不能只换回旧Fire而保留新Power。
