# 列间额外等待对照：保持本地单次波形，增加1ms回填/冷却时间

当前观察：用户把S低电平缩至约0.29us、tFire约1.3us，停放超过10分钟后再次打印比1.8us容易恢复，但仍偏红。尚未证实热积累或气泡是根因。0.29us低于现有规格书0.38us最小采样时间，这一波形属于用户已有的实验条件，本提交不把它定为正式时序，也不改写共享采样函数来强制生成它。具体允许范围仍需厂商确认。

## 本轮唯一的实验改动

HC32每次完整25地址打印、末地址全零停止、Ax0/Dx0全局清零之后，先恢复调用者的PRIMASK，再额外等待1000us。等待期间CE仍高，A/D均零，S全部高，不再发喷射指令。之后返回实时打印主循环，重装下一列SPI并拉高READY。BK的列发送函数会等READY重新拉高才返回，所以这一毫秒不会被后续电机步进或正常SPI传输掩盖。

原来的60us最小列间空闲保护仍保留。区别是：原保护可能已被通信/电机自然间隔满足；新等待是在每列结束后实际额外执行的。包括全零数据列，每次有效列函数均等待，不根据颜色选择，源字节、喷嘴命令数和点火次序保持一致。

这是降低重复频率与增加回填时间的实验，不降低单次点火能量，也不能单凭改善就证实有气泡。它不改变25地址列内同一S的周期；跨列间隔会增加，不应把跨列长间隔误当tFire。

## 这次怎么测

1. 不再擦拭、不拆装，先触发一次三条线，记录颜色及空白位置。
2. 完成后保持机器状态不变，等待约10分钟。不要拔电池、复位或中途触发打印；喷头15V按原程序在组末关闭。
3. 再触发一次三条线。两次各发送一次，不需要反复补发。纸张位置可按原测试安排。
4. 返回两次BK/HC完整日志及照片，标明哪三条是立即测试、哪三条是等待后测试。分别判断首条是否出墨、后两条是否仍偏红；深色线不等于所有颜色完整。

BK重启会重新建立冻结图缓存，输入渲染可能与上轮不完全相同。比较每次的BK预期CRC与HC接收CRC，不要求跨重启CRC相同；本轮同一作业内三阶段保持原来的冻结数据关系。

## 必须看到的HC日志

上电后增加：

```
[TPH COOLDOWN] v1 extra_idle_us=1000 after_zero_reset before_READY no_extra_fires
```

每次实际关闭喷头时增加汇总：

```
[TPH COOLDOWN_END] extra_idle_us=1000 columns=4720 min_wait_cycles=200000 max_wait_cycles=... core_hz=200000000
```

1/2/1正常完成应为4720次额外等待，HC RX仍为472000字节且CRC匹配BK。200MHz下200000个计数约1ms，max可因中断略大；如果主频不同，以min_wait_cycles/core_hz计算实际等待。日志只在上下电输出，不在每列或活动地址段打印。

整组理论累计增加约4.72秒等待，实际总时长以日志为准。没有偷偷增加预喷、剂量或等待十分钟的自动流程；这次10分钟由人记录。

## 如何判断

- 若等待后首条改善、颜色也改善：降低重复频率或增加回填时间有帮助，仍不能单独区分热积累与供墨/气泡因素。
- 若出墨仍偏红：不能说已恢复三色；也不能据此排除单次能量、采样可靠性或分色供墨问题。
- 若完全无变化：本轮1ms额外等待不足以改善现象，停止追加空打，结合实际波形和分色情况选择下一步。

## 检查与回退

GPIO/时钟/IRQ模型分别编译额外等待0与1000us：验证25+1组、末尾清零、等待期间A/D零、S高、CE高、调用者IRQ状态已恢复；等待次数/最小周期、计数回绕、NULL/OFF与上电时钟失败均检查。M4编译仍检查列内无新增调用、采样NOP块与五次半字预载不变。握手、行统计和接收CRC回归检查通过。未在用户Keil或实际硬件上验证，不承诺tFire或出墨结果。

宏TPH_COLUMN_COOLDOWN_US允许0..5000us，默认1000；设为0可编译对照基线，仍保留原60us保护。用户本轮不需要手改宏。需要Git回退时，只撤销本次冷却提交并保留本地采样校准，重新编译下载；不要强制重置整个工作区。
