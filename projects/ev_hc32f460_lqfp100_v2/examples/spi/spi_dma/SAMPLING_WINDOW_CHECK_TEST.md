# 采样窗口对照（候选）：独立68 NOP，先测量再带头打印

当前优先完成原厂样品机参照。此HC候选已准备供随后验证；不要为了样品机测试同步更新本机软件。它不保证恢复喷墨，也不证明气泡/过热。

## 为什么准备这个候选

用户先前通过44个NOP测到S低约0.29us、tFire约1.3us，出墨曾比约1.8us好，但后来隔夜后严重缺色，多次擦拭仍不能全部恢复。0.29us低于现有规格书0.38us采样下限；采样可靠性与能量同时变化，不能用这一条件判定永久坏喷嘴。

本候选去掉一个已知的超规格条件，但S和tFire都会增长，因此并非严格单因素采样试验，也不是降低能量试验。没有实际测得新宽度之前，不能称为已满足规格。

## 实际代码改变

原delay_ts_400ns定义（包括用户本地44个NOP）保留，另增tph_sampling_check.h中的TPH_Check_Sample_Delay，固定68个NOP、带编译器memory屏障。驱动只在所有原延时定义之后、第一处采样调用之前包含此头：启用时用函数宏把后续delay_ts_400ns()调用转到独立helper。正常打印、末地址零停止和全局清零的S采样都使用同一新helper。

不能把头文件移到tph_m0333n.h或原函数定义之前，否则宏会改写定义。原连续CE协议和25+1循环文本没有改动。没有改BK数据、剂量、供电、原60us保护或额外等待（仍0）。

TPH_SAMPLING_CHECK_ENABLE默认1；0时回到本地原helper。此选择是有意切换活动采样，不是说保留44-NOP定义就仍按44个NOP运行。68是指令数，不是实测纳秒值；Keil布局/总线状态仍需示波器核实。

## 后续需要用本候选时

HC仓库：

```powershell
git fetch origin
git merge --autostash --no-edit origin/codex/printer-sampling-window-check
git log -3 --oneline
```

不在当前样品机对照时同步改动。合并冲突先停止，不整体覆盖驱动或清掉本地校准。新include位于原helper与GPIO宏之间，避免修改用户曾整体转换CRLF的连续CE大块。

Rebuild All、下载HC并整机重启同步自检。启动应看到：

```
[HC32 SAMPLING] check_v1 mode=CHECK_68NOP nops=68 measured_width_unverified
```

LOCAL_HELPER表示仍走本地延时，不是候选；其nops=0是没有提供本地NOP统计，不能解读为没有延时。上电日志extra_idle_us仍须0。

先沿用此前可行的移开喷头测逻辑方法，在实际喷头连接器位置核实：四路S低至少0.38us；相邻地址同一个S下降沿的tFire，以及末地址到零停止组的周期。不要用CE宽度或跨列等待代替tFire。依据已给规格，tFire不得超过2.2us；当前15V下合适能量仍需厂商给出范围，不能仅由满足采样下限推定。

若S低不足0.38us或tFire超过2.2us，先不带头测试、不继续删NOP。确认测量后，用保持不变的BK逐D版本22ba79b只发送一组12条，不额外预喷、不增加循环。回传实际S/tFire和两端完整日志/纸面，不反复补打到结果满意。
